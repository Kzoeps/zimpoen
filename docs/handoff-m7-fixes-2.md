## 4. Verified facts (checked against the installed 1.4.0 `dist`, or by running it)

- **Durable code mode.** `CodemodeCall.execute` takes the time limit only from `parseCodemodeSource(code).options.timeoutMs`, stores `run.start.deadline = now + timeout`, and on a rerun refuses with "Script timed out: its deadline passed while it was interrupted." when `deadline <= api.now()`; otherwise it starts the VM with `timeoutMs: remaining`. The sandbox's own `timeoutMs` is not read on this path. The timeout error reads "Script error:\nScript timed out: Execution timed out after N ms". A nested tool with `replay: "safe"` that was in flight at the restart may run again by itself (my stalled test tool ran twice): that is Durable's, the script itself is not restarted.
- `parseCodemodeSource` returns `code` = the input from the first line break on when there is an options line (so `code !== source` tells), else the whole input; a malformed or misplaced options line throws `CodemodeSourceError` (the bounded tool lets it through as the tool error).
- `AppDb.transaction` nests as savepoints (a helper may open one inside its caller's). `ALTER TABLE … ADD COLUMN` works on the `STRICT` ledger tables (migration 004).
- `nameKey`: a JS look-behind with a quantifier works (`(?<=[\p{Script=Latin}…]\p{M}*)\p{M}+`). `nameKey` of a merchant drops words with three or more digits (`merchantKey`), which is why "DRUK MART 123456" is the merchant "druk mart".
- A merchant's usual category is filled in by `add_expense` when none is given (so a test that needs uncategorized entries of a merchant must write them before any categorized one).
- PDFKit: `new PDFDocument({ bufferPages: true })`, then `doc.bufferedPageRange()`, `doc.switchToPage(i)`, `save/rotate/fillOpacity/restore` draw a watermark on finished pages.
- `ImportPreviewCard`'s new fields (`matchCount`, `matches`, `warnings`, sample `match`) and `ImportResultCard.skippedMatches` are **optional**, so a preview stored before them still renders and replays.
- Bundle smoke (this session): 25 migrations applied incl. `ledger/004_undo`; `import_csv` on a Dr/Cr file read the direction column and listed the typed lunch as a match; `confirm_import` skipped it; `propose_undo_import` then a typed `YES` removed the import (balance back to Nu. 9,550.00); `preview_invoice` made a 2.4 KB PDF under `workspace/invoices/previews/`, served as `attachment` with `nosniff` and CSP `sandbox`, PREVIEW across the page (looked at with `pdftoppm`); `codemode` loop ended at ~30 s with the server answering meanwhile; a `codemode` script wrote 25 entries; `recategorize` preview → confirm; `record_settlement from "Pema"` refused; SIGTERM closed it.

## 5. Decisions of this session (★ = for the coordinator to veto; each is cheap to reverse)

1. ★ **Time limits:** 30 s default, 120 s maximum, applied by wrapping the tool (not by the sandbox option); the two hooks for tests are `codemodeLimits` options, no environment variable.
2. ★ **Scripts may call every tool the Accountant has** (the docs were corrected instead of restricting the writes to `callers: ["model"]`); the approval hook still applies to nested calls.
3. ★ **Probable repeats:** ±2 days, exact signed amount, same account, **chat and receipt entries only** (an entry another import wrote is never a match), left out by default. A row that was left out cannot be added by a later `confirm_import` of the same import (its rows are cleared on confirm): run `import_csv` again and confirm with `include_matches`; the result text says so.
4. ★ **Future-dated rows are left out** (listed as problems), not just flagged.
5. ★ **An undone import stays `status = imported` with `undone_at`** (a status value would need a table rebuild); `confirm_import` on it is refused.
6. ★ **`recategorize` changes its default** from substring to the merchant's whole key; the `> 20 → confirm` rule applies to ids too; the preview call records nothing.
7. ★ **`sumsOf` no longer counts transfers** (affects the list totals; the wrap-up facts already used `kind: income`).
8. ★ **A settlement with a partial name is a tool error** with guidance (not an ok result), `new_person: true` the way out; `lookalikes` for bills flags any shared word now.
9. ★ **`preview_invoice` is an everyday tool** (the Accountant is offered 21), shows a month that has an invoice with a warning, and uses one file per call.
10. ★ **`parseAmountText` is stricter** (unknown letters mean "not an amount") and `detectDecimalSeparator` reads all-three-digit groups as thousands; both are guesses a bank file could contradict, and the tool output does not yet say which one it made (no preview note for the thousands case).
11. ★ `nameKey` changed for non-Latin scripts (keys of existing rows in a dev database would differ; none is expected since M7 never shipped).
12. Small: after a confirm the note is "Entries dated **before** <stated day> are already part of that balance" (it said "on or before", wrong for the stated day itself); singular/plural wording of the match lines; `Harness.start(intervals?, more?)` in `apps/server/test/domain-support.ts` takes `StartServerOptions` overrides.
