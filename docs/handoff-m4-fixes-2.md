### Verified facts / quirks (new)

- **Durable 1.4.0 declares `Harness.submissionByRequest(...)` in `types.d.ts` but the `Harness` class does not have it at runtime** (`harness.submissionByRequest is not a function`); the `Session`'s transaction has it: `harness.commit(tx => tx.submissionByRequest(conversationId, requestId), BACKGROUND_CONTEXT)`. Worth one line to the Durable maintainers.
- `GenerationTask` + `hook(GenerationTask, { beforeRequest(request, api) })` works from an extension (`api.conversationId`, `request.messages` are the provider messages; the daily input's `model` message is the user message with the request text).
- `reader.scanLines({startLine,endLine})` returns `[start,end)` that **excludes the newline ending the last selected line** (so a blank line selects 0 bytes), except when `endLine` is beyond the last line, where `end === size` and the file's final newline is included.
- The TS lib of this repo has no `String.prototype.isWellFormed` (use `encodeURIComponent(name)` throwing on a lone surrogate).
- **Unrelated flake, not touched**: `apps/server/test/agents.test.ts › ensureAgents › adopts the conversations a crashed start created…` failed twice in whole-file runs under load and then passed 3×; cause: `listAgentRows` orders `BY created_at, id`, adopted rows share a millisecond so `accountant` sorts before `health`. Suggested fix for the coordinator: compare as sets/sorted in that test (or order by rowid). Say so in the report.
